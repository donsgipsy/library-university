# Правила внесения и проверки изменений

## Ветвление
- Основная ветка: `main`.
- Тематические ветки создаются с префиксом: `docs/` (для документации), `feature/` (для кода), `fix/` (для исправлений). Пример: `docs/uc-02-update`.

## Коммиты
- Сообщение коммита должно быть информативным и описывать результат.
- Примеры: "Уточнены предусловия UC-02", "обновление", "правки".

## Запросы на слияние (Pull Request)
1. Перед созданием PR убедитесь, что ваша ветка актуальна относительно `main`.
2. В описании PR укажите: цель изменения, связанные требования (ФТ/UC), список изменённых файлов и способ проверки.
3. **Взаимная проверка**: PR должен проверить другой участник команды. Проверяющий оставляет отзыв, автор вносит правки. Только после одобрения ответственный выполняет слияние.

## Правило актуальности документов
- Содержательные изменения вносятся **только** в Markdown-файлы (`docs/md/`, `docs/README.md`).
- Word-версии (`docs/doc/`, `docs/report.docx`) обновляются из Markdown (например, через Pandoc или копированием с применением стилей) **после согласования** и перед каждой сдачей.
- Исправления только оформления допустимы напрямую в DOCX, но должны быть синхронизированы с Markdown.
- Исходники диаграмм (`.drawio`/`.puml`) и их PNG-экспорты обновляются вместе.
